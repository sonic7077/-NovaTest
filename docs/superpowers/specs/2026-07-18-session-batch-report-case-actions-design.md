# 会话校验、批量报告与用例操作设计

## 目标

修复接口执行把无效会话误判为通过的问题；为一次批量执行提供一份可追溯的汇总报告；补全测试资产列表的选择、执行与删除操作。

## 范围

- 接口执行器正确识别无标识加密登录响应，并仅把解包得到的字符串写入内存会话 token。
- 业务请求以解包后的业务状态为最终判断依据；外层协议成功而业务体提示失败时，步骤必须失败。
- 每个批次提供一份聚合报告，包含汇总数据和各用例的步骤结果、脱敏请求与响应证据。
- 所有报告以 `Asia/Shanghai` 本地时间显示，格式为 `YYYY-MM-DD HH:mm:ss`。
- 测试资产列表支持全选、批量删除、单条执行和单条删除。

## 非目标

- 不修改加密算法、请求签名或已有只读接口用例定义。
- 不持久化、展示或写入 token、密码、密钥、密文与签名。
- 不改变删除后仍可查看既有运行与报告的存储语义。
- 不支持跨项目或跨执行类型的混合批次。

## 接口执行与会话

`CmsApiRunner` 统一将外层响应解包为业务值：明确标记加密的响应必须解包；无标识字符串响应尝试解包，失败时保留原字符串。`authenticate()` 只接受最终业务值为非空字符串的登录结果，将其存入调用方提供的内存 session。

请求结果先读取外层协议状态，再读取解包业务对象的 `status` 或 `errcode`。若业务对象提供状态，该状态覆盖外层结果。这样 `token 无效` 等业务失败会在 `RunService` 中记录为失败，而不会生成误导性的通过报告。单条执行创建一个 session；批量 API 执行创建并共享一个 session，整批仅登录一次。

## 批量汇总报告

新增 `GET /api/batches/:id/report`。该端点读取批次和已持久化的运行记录，并调用 `renderBatchReport(batch, runs)` 输出 HTML。

报告显示批次名称、状态、开始和结束本地时间、总耗时、通过与失败计数；随后按批次中用例顺序输出每份运行的标题、状态、起止时间和既有步骤证据。每份步骤证据复用现有的转义与脱敏逻辑。批量历史只展示一个“查看汇总报告”链接；单条报告接口仍保留。

## 本地时间

报告服务导出 `formatLocalTime(value)`，使用固定的 `Asia/Shanghai` 时区和中文数字格式产生 `YYYY-MM-DD HH:mm:ss`。运行时间继续以 ISO UTC 字符串持久化，避免数据库迁移与时区歧义。

## 用例列表操作

表头选择框控制当前筛选结果中的所有用例；选择状态写入既有 `selectedCaseIds`。当可见用例全部选择时为选中态，部分选择时显示不确定态。

选择栏提供“批量执行”和“批量删除”操作。批量删除需要一次明确确认，逐条调用已有删除端点，随后刷新列表、选择状态和批量历史。单条操作区增加执行、编辑和删除图标按钮。单条执行调用既有运行端点，跳转工作台展示运行过程，并刷新历史；单条删除沿用同样的确认与历史保留行为。

- 为列表模板增加全选、批量删除、单条执行与删除控件断言。
