# 工作台、执行中心与质量报告设计

**日期：** 2026-07-19
**状态：** 已确认，等待规格审阅

## 目标

将 NovaTest 现有首页中的执行过程、日志、执行策略和报告预览拆分为三个职责明确的页面，并将执行改为异步、可观察的持久化任务。

- **工作台** 只呈现真实完成运行的质量趋势与质量概览。
- **执行中心** 承担单条和批量任务的排队、实时步骤进度、日志和最终结果入口。
- **质量报告** 作为历史报告索引，按条件检索并打开单条或批量报告。

本设计不改变 Web UI、CMS API 用例的执行语义，不修改现有 Midscene 模型配置能力，也不自动重跑失败任务。

## 信息架构

侧栏增加三个可路由入口：

| 页面 | 路由 | 责任 |
| --- | --- | --- |
| 工作台 | `#/dashboard` | 真实质量统计与图表，不显示进行中的步骤或日志。 |
| 执行中心 | `#/executions` | 所有已提交的任务、实时状态、进度、步骤日志和报告入口。 |
| 质量报告 | `#/reports` | 已完成单条运行与批量汇总报告的可筛选历史列表。 |
| 测试资产 | 现有资产路由 | 用例与项目维护，以及发起单条或批量执行。 |
| AI 模型配置 | 保留现有配置入口 | Midscene/视觉模型连接、执行策略与凭据配置；不迁移到工作台。 |

测试资产与 AI 模型配置均保持为侧栏一级入口，不能被工作台、执行中心或质量报告替代。资产页提交执行请求后立即跳转至 `#/executions?focus=<task-id>`；用户无需停留在资产页等待 HTTP 请求结束。模型配置的现有接口、字段和未配置状态本次不改变，执行中心只读取运行事实，不提供凭据编辑能力。

## 异步执行模型

### 状态与持久化

批量任务、单条运行及其步骤均在状态变化时写入既有 store。状态值固定为：

- 任务/运行：`queued`、`running`、`passed`、`failed`。
- 步骤：`queued`、`running`、`passed`、`failed`。

新字段保存运行历史快照，避免删除或改名用例后统计失真：

- `test_runs.project_id`、`test_runs.target`。
- `test_batches.target`。

已有数据迁移时从仍存在的用例补齐快照；无法判定的旧记录仍可打开报告，但不计入按类型统计。任务与运行的 `startedAt` 在真正开始时写入，`finishedAt` 只在终态写入。

### 调度与进度

新增进程内 `ExecutionService` 作为唯一调度入口。它接收并持久化新任务后通过事件循环异步执行，HTTP 请求立即以 `202` 返回已排队的对象。当前版本的并发规则如下：

1. 单条用例提交后独立排队并执行。
2. 每个批量任务内严格串行执行用例，失败后继续后续用例。
3. API 批量任务在批次开始时创建一个 `CmsApiRunner` session，供同批所有 API 用例复用；这一既有行为保持不变。
4. `RunService` 每次创建运行、开始步骤、完成步骤、失败重试、完成运行时都调用进度回调，`ExecutionService` 将快照写入 store。

服务重启不恢复正在运行的任务。应用启动时会把残留的 `queued` 或 `running` 任务标记为 `failed`，并记录“服务重启导致任务中断”的可见错误，防止页面永久显示运行中。

### API 契约

保留既有 URL，并将提交接口调整为立即响应：

| 方法 | URL | 结果 |
| --- | --- | --- |
| `POST` | `/api/cases/:id/runs` | 返回状态为 `queued` 的单条运行。 |
| `POST` | `/api/batches` | 返回状态为 `queued` 的批量任务。 |
| `GET` | `/api/runs/:id` | 返回最新运行和有序步骤快照。 |
| `GET` | `/api/batches/:id` | 返回最新批量任务、关联运行和聚合进度。 |
| `GET` | `/api/executions` | 返回执行中心任务列表；支持 `projectId`、`status`、`target`，按最近更新倒序。 |
| `GET` | `/api/dashboard?range=today|7d|30d` | 返回仅基于终态运行的概览、每日趋势、目标分布、失败步骤和最近完成运行。 |
| `GET` | `/api/reports` | 返回可打开的单条/批量报告索引；支持 `projectId`、`status`、`target`、`range`。 |

`GET /api/executions` 的每条任务包括已完成用例数、总用例数、已完成步骤数、总步骤数、当前运行名称、最近日志时间与报告链接。接口不返回密码、token、验证码、Google 密钥或 CMS 加密配置。

## 工作台

工作台顶部提供“今日 / 最近 7 天 / 最近 30 天”分段时间选择，默认最近 7 天。所有图表和指标随选择重新请求服务端聚合数据。

展示内容：

1. 完成运行数、通过率、平均耗时、自动化用例总数四个指标。
2. 每日通过/失败运行趋势图。
3. Web UI 与接口测试的完成运行分布图，以及各自通过率。
4. 最近失败步骤，包含用例名、项目、失败原因、完成时间和报告入口。
5. 最近完成报告摘要，包含单条/批量标识、状态、时长、完成时间和打开报告操作。

图表用原生 HTML/CSS/SVG 绘制，不引入外部图表依赖。无完成记录时，指标显示 `--` 或 `0`，图表区域显示“所选时间范围内暂无已完成执行记录”；不得保留硬编码百分比、趋势或次数。页面不显示执行进度、运行日志、模型状态、策略开关或“上次测试报告”卡。“进入测试资产”和“模型配置”保留可见入口：前者引导到项目与用例库，后者保持现有 AI 模型配置页。工作台只移除它们的重复信息展示，不删除任何功能。

## 执行中心

执行中心默认显示最近任务，并提供项目、类型（Web UI/接口）和状态筛选。任务列表包含：名称、项目、类型、创建/开始时间、状态、用例进度、步骤进度、当前用例和已用时。

选择一个任务后，右侧详情显示：

- 进度条和当前用例/步骤；
- 已完成与失败的步骤列表；
- 实际 runner 日志与失败重试记录；
- API 运行的已脱敏请求/响应证据或 Web UI 截图证据摘要；
- 终态后的单条报告或批量汇总报告按钮。

当页面可见且存在 `queued` 或 `running` 任务时，前端每 1.5 秒轮询任务接口；切换路由、页面隐藏或所有任务终态时停止轮询。列表与详情按服务端时间刷新，不能使用计时器伪造进度。

## 质量报告

质量报告页面显示已完成任务的报告索引，按项目、目标类型、通过/失败状态和时间范围过滤。批量任务只显示一条汇总报告；不属于批量的单条运行显示单条报告。每行显示名称、项目、类型、状态、开始/结束本地时间、耗时、通过/失败用例数和“查看报告”操作。

所有时间继续以 `Asia/Shanghai` 本地时间格式展示。报告正文沿用既有脱敏规则：业务解包内容可展示，认证 token、密码、验证码、Google 密钥、AES/签名配置及其嵌套字段必须替换为 `********`，失败 API 步骤同样保留已脱敏的请求体与响应内容。

## 错误处理与兼容性

- 用例或批量参数校验继续在提交前执行，项目/类型混选仍返回现有错误。
- 调度器捕获未处理 runner 异常并把对应运行和批量落为 `failed`，执行中心显示错误文本，不让请求悬挂。
- 原有 `/api/runs/:id/report` 与 `/api/batches/:id/report` 保持可用；已删除用例的历史报告继续可访问。
- 现有批量、CMS 会话复用、报告脱敏和证据访问控制回归测试必须继续通过。

## 验收标准

1. 发起单条或批量执行后，提交接口在 runner 完成前返回 `202` 和 `queued` 状态；后续查询可观察到 `running`、步骤变化及终态。
2. 批量执行中，执行中心能看到用例/步骤进度和真实重试日志；同批 CMS API 用例只登录一次。
3. 工作台不包含过程面板或静态演示数据，时间范围切换只统计选定范围的已完成运行。
4. 执行中心和质量报告入口均可直接路由访问，筛选和报告链接有效。
5. 测试资产与 AI 模型配置均继续以一级入口存在，已有配置功能和资产 CRUD 不受影响。
6. 历史报告、证据与敏感字段脱敏行为不回归；全量自动化测试通过。
