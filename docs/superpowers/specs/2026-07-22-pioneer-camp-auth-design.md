# 先锋营自动化测试平台品牌与登录设计

## 目标

将产品品牌统一为“先锋营自动化测试平台”，移除原型阶段的空间切换文案，并为本地部署提供一个可持久化的管理员登录与个人资料维护能力。

## 范围

- 页面标题、侧边栏品牌和登录页使用“先锋营自动化测试平台”。
- 删除“当前空间”和“Atlas Commerce”控件，不提供空间切换功能。
- 初始化一个本地管理员账号：用户名 `admin`，初始密码 `admin123`。
- 未登录用户只能使用登录页；登录后才可读取或操作测试资产、执行与报告接口。
- 已登录管理员可更新显示姓名、岗位和邮箱，及独立修改密码。
- 侧边栏展示当前登录账号和资料入口，并提供退出登录。

本次不提供多用户管理、注册、找回密码、角色权限配置、LDAP/SSO 或 CMS 账号联动。测试平台账号与 CMS 接口测试的环境凭证完全独立。

## 架构

账户资料存入现有 SQLite 数据库的 `users` 表，密码以 Node 原生 `crypto.scrypt` 加盐派生值保存，绝不存储明文密码。SQLite 初始化时仅在没有 `admin` 用户时创建默认管理员，因此既有资料不会被重置。

认证使用服务端内存会话：成功登录生成不可预测的随机会话标识，作为 `HttpOnly`、`SameSite=Lax` Cookie 下发；服务端会话映射到用户 ID。每次受保护的 API 请求都读取 Cookie 并确认会话有效。退出登录会失效服务端会话并清除 Cookie。服务重启会使会话失效，用户需重新登录，账户资料仍保留在 SQLite。

生产入口 `server/index.js` 明确启用认证中间件。`createApp` 保留一个仅供现有业务测试使用的可关闭认证开关，避免将每个既有执行器测试改写为登录流程；新增认证集成测试会显式启用认证。

## 接口

公开接口：

- `POST /api/auth/login`：接收 `{ username, password }`；成功返回 `{ user }` 并设置会话 Cookie；错误凭证返回 401，不透露用户名是否存在。
- `POST /api/auth/logout`：清理当前会话与 Cookie，返回 204。
- `GET /api/auth/session`：已登录返回 `{ user }`，未登录返回 401。

受保护接口：除上述认证接口与健康检查外，所有 `/api/*` 需要有效会话。未认证请求统一返回 401 `{ error: '请先登录' }`。

- `PUT /api/auth/profile`：更新当前用户的 `{ displayName, jobTitle, email }`；显示姓名与岗位为必填且有长度限制，邮箱为空或满足基本邮箱格式。
- `PUT /api/auth/password`：接收 `{ currentPassword, newPassword }`；验证旧密码后更新密码哈希，密码至少 8 位；失败不改变现有密码。

用户对象只返回 `{ id, username, displayName, jobTitle, email }`，不返回密码哈希或盐值。

## 前端体验

初次打开应用时，先读取当前会话。未登录时完整显示独立登录页，包含产品名、用户名、密码和登录按钮；登录失败显示明确但不泄露账户存在性的错误信息。初始凭证 `admin / admin123` 在登录页以低调提示展示，方便本地首次使用。

登录后显示既有工作台。侧边栏左下只保留当前用户按钮：头像使用显示姓名的前两个字符或用户名首字母，主文字为显示姓名，次文字为岗位。点击该按钮进入“个人信息”页面，能保存资料、修改密码和退出登录。页面刷新时从会话恢复用户信息；会话过期时清空客户端状态并切换回登录页。

## 数据与迁移

SQLite 升级为 `user_version = 10`，新增：

```sql
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  username TEXT NOT NULL UNIQUE COLLATE NOCASE,
  password_hash TEXT NOT NULL,
  password_salt TEXT NOT NULL,
  display_name TEXT NOT NULL,
  job_title TEXT NOT NULL,
  email TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

内存存储实现与 SQLite 使用相同的用户存取契约，以支持认证 API 测试。默认管理员仅由应用启动/存储初始化确保一次；更新资料和密码均写入持久化存储。

## 错误处理与安全边界

- 认证失败、失效会话与缺少会话均返回 401；不重定向 API 请求。
- 不记录用户输入的密码、密码哈希、盐值或会话标识。
- 修改密码要求当前密码，成功后撤销该用户已存在的所有会话并要求重新登录。
- 个人资料保存失败时留在当前页面并显示错误，不覆盖已加载资料。
- 登录 API 增加基础请求体校验；空用户名或密码返回与错误凭证相同的 401 响应。

## 验收

1. 页面不再出现 NovaTest、当前空间、Atlas Commerce、张伟或 QA Engineer 的演示身份。
2. 新数据库和既有数据库首次启动后都有可登录的 `admin / admin123`。
3. 未登录访问受保护 API 返回 401，登录后可访问；退出或服务重启后再次访问返回 401。
4. 资料修改刷新后仍显示，密码修改后旧密码不可登录、新密码可登录。
5. 密码和会话值不会出现在 API 返回、前端状态展示或日志中。
6. 既有用例、项目、执行与报告数据及 API 语义不受数据库迁移影响。

## 自检

- 无待定项或模糊的默认账号行为。
- 本地平台认证与 CMS 环境凭证明确隔离。
- SQLite 持久化、会话失效和前端切换行为一致。
- 本次范围限制为单管理员与个人资料，不引入多用户管理系统。
