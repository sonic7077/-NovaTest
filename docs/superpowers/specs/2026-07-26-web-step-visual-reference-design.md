# Web UI 步骤参考图片设计

## 目标

让 Web UI 用例的每个步骤可保存一张或多张参考图片及对应文字说明。执行时，Midscene 同时接收步骤文字和参考图完成页面识别、操作或信息提取；步骤完成后，再以当前页面截图和参考图进行语义一致性校验。运行报告必须保留参考依据、执行证据、校验结论和模型理由。

本设计也将更新“无极灯塔 - 任务清单识别与新建任务”用例，使它生成唯一任务标题并在创建后保存可校验截图。

## 范围

- 仅扩展 Web UI 用例；接口用例编辑器、运行器和报告不增加图片控件。
- 每个 Web UI 步骤可绑定零到多张参考图片。每张图片均有独立说明。
- 允许 PNG、JPEG、WebP，单张不超过 5MB，资产只能属于当前用例。
- 继续复用已有的 `test_steps.visual_checks_json`、上传接口和 `data/case-assets/<caseId>/` 存储结构。
- 保持无参考图片的既有 Web UI 用例、历史报告和执行路径不变。
- 不实现像素级差异、区域裁剪、图片版本管理或跨用例复用。

## 数据模型与图片访问

一个步骤的 `visualChecks` 保持以下结构：

```js
{
  id: 'visual-uuid',
  assetPath: 'case-id/visual-uuid.png',
  source: 'upload' | 'run',
  description: '创建成功后，列表中显示新任务标题和测试任务清单'
}
```

保存用例时，服务端继续验证图片路径以当前用例 ID 开头、来源合法且说明非空。新增只读图片接口，按用例 ID 与已绑定资产白名单读取缩略图；不公开 `data/case-assets` 静态目录。新建用例尚无 ID 时，编辑器显示“保存用例后可上传参考图片”，避免临时资产孤立。

## 编辑体验

每张 Web UI 步骤卡在文字描述下方增加“参考图片”区域：

1. 上传按钮与隐藏文件选择器；上传成功后立即将图片绑定到该步骤草稿。
2. 缩略图、图片文件标识、可编辑的识别/校验说明，以及删除按钮。
3. 一张步骤可继续添加多张图片；删除只解除步骤引用，不自动删除历史报告中的证据。
4. 保存用例时，`readCaseFromForm` 读取视觉检查数据，`applyCase` 完整回显。

参考图的文字说明应描述业务状态或页面元素，而不是要求像素完全一致。例如：“任务列表显示创建成功后的新任务，标题可见，所属清单为测试任务”。

## 执行流程

Midscene 当前版本的 `TUserPrompt` 原生支持 `{ prompt, images, convertHttpImage2Base64 }`。WebRunner 为每个带有图片的步骤将受控的本地图片绝对路径转为 Midscene 图片输入，不引入第二套模型调用。

1. RunService 创建运行时生成 `random6`：每次运行唯一的六位数字，并放入 `run.variables`；步骤中的 `{{random6}}` 在执行前解析。
2. WebRunner 打开页面并完成项目公共登录后，将步骤文字与参考图一起传给 `aiAct`、`aiAssert` 或 `aiQuery`。这使图片可用于操作定位和内容识别。
3. WebRunner 截取当前步骤页面，生成既有运行证据。
4. 对每张参考图调用 Midscene `aiAssert`，提示模型以步骤描述和图片说明为验收条件，明确对比当前页面和参考状态；时间、随机任务标题中的数字、广告及非关键动态内容不作为失败条件。
5. 所有视觉检查通过后，步骤标记为通过，并记录每张图片的结果。任一检查失败或模型无法确认时，步骤失败，附上模型原因、当前截图及已完成的视觉结果；既有的一次重试仍生效。

运行结果增加：

```js
{
  id: 'visual-uuid',
  status: 'passed' | 'failed',
  reason: '模型给出的简短判断理由',
  baselinePath: 'case-id/visual-uuid.png',
  screenshot: 'run-id/step-4-attempt-1.png'
}
```

## 报告与错误处理

报告在对应 Web UI 步骤中展示参考图片、执行截图、通过/失败状态和模型理由。图片加载失败、资产越界、模型图片请求失败或语义不一致都不得伪造通过：保留已截取的运行证据和明确错误信息。历史报告使用运行快照与受控图片读取接口；删除用例后，已有报告继续可读。

## 灯塔用例

用例“无极灯塔 - 任务清单识别与新建任务”调整为以下四步：

1. 确认“我负责的”任务列表已加载。
2. 结合步骤参考图识别可见任务的标题、负责人、状态、截止日期与任务清单字段，并保存截图证据。
3. 点击“新建任务”，选择任务清单“测试任务”。
4. 在任务标题中输入 `衡川测试{{random6}}`，创建任务后确认该标题出现在“我负责的”列表且任务清单为“测试任务”；保存创建成功后的截图并执行视觉校验。

第 4 步会改变外部系统数据。平台只在用户提交单条或批量执行且明确授权写操作时执行它；实现与自动测试阶段不会自动创建外部任务。

## 验收标准

1. 已保存 Web UI 用例的每一步可上传、预览、填写说明、删除并持久化多张图片。
2. 新建用例在首次保存前不会出现可用上传动作；保存后可绑定图片。
3. 带图片的 `action`、`assert`、`query` 均将图片作为 Midscene 原生多模态输入，且在步骤截图后进行视觉校验。
4. 无图片步骤保持原有 Midscene 调用和报告表现。
5. 视觉失败会记录理由、参考图与失败截图，且不掩盖原步骤失败原因。
6. 灯塔用例有四步，使用 `衡川测试{{random6}}`，第四步包含创建后列表断言和截图证据。
7. 单元、接口和界面测试覆盖上传、保存/回显、运行器多模态调用、视觉失败证据、随机变量和灯塔用例数据。
