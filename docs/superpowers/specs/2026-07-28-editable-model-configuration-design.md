# 可编辑 AI 模型配置与部署健康设计

## 目标

管理员可以在平台内维护 Midscene Web UI 运行器的模型地址、模型名称、模型适配器和 API Key。保存后，新提交的 Web UI 任务使用新配置；接口测试、正在运行的任务和 CMS 加密凭据不受影响。

同时，平台需要在模型配置页面直接展示 CMS 执行器状态及缺失配置项，避免用户只能从失败报告中发现部署环境问题。

## 方案选择

采用“数据库保存运行时覆盖 + 部署密钥加密”的方案。

环境变量仍作为首次启动和故障回退配置。管理员保存的模型覆盖配置写入 SQLite，并优先于环境变量使用。API Key 不以明文保存在数据库中；服务使用部署环境中的 `PLATFORM_CONFIG_ENCRYPTION_KEY` 进行 AES-256-GCM 加密与解密。

不采用浏览器直接写 `deploy/test.env`：应用运行在容器中，页面写宿主机部署文件既不可靠也会扩大权限边界。也不采用明文 SQLite 保存 API Key。

## 数据与安全

新增单行平台设置表，保存非敏感字段和加密后的 API Key。公开 API 只返回脱敏 Key、是否已配置 Key、配置来源与更新时间。

更新接口要求已登录管理员身份。Key 输入框为空表示保留现有 Key；显式清空必须通过独立的清除开关确认。日志、报告和健康接口不得返回明文 Key、加密密文或加密密钥。

若服务未设置 `PLATFORM_CONFIG_ENCRYPTION_KEY`，页面仍可读取现有状态，但拒绝保存包含 API Key 的模型配置，并明确提示需要部署侧补齐该变量。

## 运行器更新

服务启动时按“数据库覆盖配置 > 环境变量”构建 Web UI 运行器。更新成功后，后端异步创建新的生产运行器，并通过可替换代理切换给后续任务。原运行器会保留到当前会话关闭；已入队或正在执行的任务不被中断。

如果新模型配置无法初始化，保存失败并保留当前可用运行器与配置。健康接口返回当前运行器状态及最后一次更新错误（如有）。

## UI

AI 模型配置页面改为紧凑编辑表单：服务地址、模型名称、模型适配器、API Key 和“清除已保存 Key”复选框。页面显示当前配置来源、最后更新时间、Web UI 运行器状态，以及 CMS 接口执行器状态。

API Key 永远不回填。保存按钮在请求期间禁用，保存结果通过现有提示条反馈。CMS 状态区域仅展示缺失字段名，不展示任何值。

## CMS 部署问题

截图中的 CMS 用例失败来自容器启动时缺失 `CMS_BASE_URL`、加密参数、账号和客户端元数据。CI 部署脚本仅在首次部署生成 `deploy/test.env`，后续不会覆盖，因此需要在服务器 `/opt/auto_test/deploy/test.env` 补齐受控 CMS 配置并重启容器。

此类配置不纳入可编辑模型表单，也不写入 SQLite。模型配置页面和 `/api/health` 将继续把 CMS 执行器标记为不可用并返回缺失字段名。

## 验证

- 单元测试覆盖加密/解密、脱敏、空 Key 保留、清除 Key、缺失部署加密密钥和失败回滚。
- API 测试覆盖管理员访问、未登录拒绝、保存后健康状态与 CMS 缺失信息。
- 浏览器验证表单编辑、脱敏回显、保存后状态更新和 CMS 健康提示。
- 完整 `npm test` 回归，并通过部署健康接口确认服务可用。
