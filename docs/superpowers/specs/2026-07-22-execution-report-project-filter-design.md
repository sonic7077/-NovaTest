# 执行中心与质量报告项目筛选设计

**日期：** 2026-07-22  
**状态：** 已确认，等待规格审阅

## 目标

在执行中心和质量报告中按测试项目查看运行与报告。两个页面默认展示全部项目，用户可在页面内自行选择项目进行二次筛选。

## 范围

本次仅调整以下前端筛选和请求行为：

1. `#/executions` 执行中心。
2. `#/reports` 质量报告。

不修改项目 CRUD、测试资产、工作台、执行调度、SQLite schema、执行报告正文或既有 API URL。

## 筛选交互

两个页面的筛选栏首位都增加项目下拉框：

- 控件默认值为 `全部项目`，对应空 `projectId` 参数。
- 选项由现有 `GET /api/projects` 返回的项目生成；显示项目名称，值使用项目 ID。
- 每个页面维护独立的选择值。切换执行中心和质量报告不会隐式同步筛选范围。
- 用户改变项目后立即刷新当前页面数据，保留该页面其他已选条件。

执行中心的项目下拉框与现有状态、类型筛选并列。质量报告的项目下拉框与状态、类型、时间范围筛选并列。

## 数据请求与状态

服务端现有端点已经支持 `projectId`，前端按下列方式调用：

| 页面 | 请求 |
| --- | --- |
| 执行中心 | `GET /api/executions?projectId=<id>&status=<status>&target=<target>` |
| 质量报告 | `GET /api/reports?projectId=<id>&status=<status>&target=<target>&range=<range>` |

未选择具体项目时不发送 `projectId`。前端继续使用 `URLSearchParams` 构建请求，避免空参数和手工拼接错误。

执行中心的轮询沿用现有 1.5 秒规则，并在每次刷新时复用当前项目、状态和类型筛选。项目筛选导致当前选中任务不在结果中时，清除旧 ID，并自动选中筛选结果的第一条任务；没有任务时展示既有空状态。

## 失败与边界

- 项目选项加载失败时，保留“全部项目”，并通过现有 toast 展示“无法读取测试项目”。执行和报告列表仍可按默认范围加载。
- 项目删除、项目无任务或项目无报告时，已选项目值不产生异常；页面分别显示“暂无执行任务”或“暂无记录”。
- 空项目 ID 始终等价于全部项目，不允许向接口发送字符串 `undefined` 或 `null`。
- 不在本次改造中引入跨页面全局项目状态、URL 筛选参数或新的后端接口。

## 验收标准

1. 执行中心和质量报告均有项目下拉框，默认“全部项目”。
2. 项目选项来自真实项目列表；选择项目后对应请求携带正确的 `projectId`。
3. 状态、类型、时间范围和项目筛选能同时生效。
4. 执行中心轮询不丢失项目筛选，且切换项目后不会显示旧项目详情。
5. 项目不存在、无任务或无报告时显示正确空状态，不出现未捕获错误。
6. 全量自动化测试与浏览器验证通过。
