# 执行中心详情面板设计

**日期：** 2026-07-19
**状态：** 已确认，等待规格审阅

## 目标

将执行中心右侧的纯文本详情替换为可随任务状态更新的“结论优先 + 过程展开”面板。用户可在不打开报告的情况下判断任务是否通过、是否存在风险、当前执行到哪里以及失败原因；仍可从面板进入既有报告。

## 状态模型

详情结论基于已有任务、运行和步骤快照计算，不修改 runner、数据库 schema 或 API 执行逻辑。

| 展示结论 | 条件 | 主信息 |
| --- | --- | --- |
| 执行中 | 任务为 `queued` 或 `running` | 当前用例、当前步骤、用例/步骤进度、已用时。 |
| 通过 | 任务为 `passed`，且无步骤重试 | 完成度、通过用例/步骤、总耗时、报告入口。 |
| 需关注 | 任务通过但存在重试；或任务中断、执行器未配置等可见风险 | 通过结论、风险原因、重试次数及报告入口。 |
| 失败 | 任务为 `failed` | 首个失败步骤、失败原因、已完成度、报告入口。 |

## 页面布局

右侧详情使用一个连续的工具面板，内部以分隔区划分内容，不嵌套浮动卡片。

1. **结论区**：状态图标、结论标题、简短描述、类型标签和完成时间/已用时。
2. **进度区**：环形进度与两个固定统计项，用例完成数和步骤完成数。执行中显示当前用例及阶段；终态显示通过/失败分布。
3. **步骤时间线**：按批量内用例顺序列出步骤。每项包含状态图标、步骤名称、重试计数、错误文本和 API/Web 证据摘要；运行中步骤以轻量动画标识。
4. **操作区**：终态任务显示“查看测试报告”图标按钮。报告 URL 来自现有服务端汇总，不构造新链接。没有终态报告时隐藏操作。

批量任务详情读取 `/api/batches/:id` 的关联运行和步骤；单条任务读取 `/api/runs/:id`。列表聚合接口只负责选择任务，不承担详情证据内容。

## 风险与脱敏

- 重试后通过显示为“需关注”，不将其混同于无风险通过。
- 步骤失败或中断显示错误文本与状态；API 步骤只展示已持久化的脱敏 action、HTTP 状态、业务状态和耗时。
- Web UI 步骤只显示已注册截图数量和报告入口，不直接拼接未授权文件路径。
- token、密码、验证码、Google 密钥、AES/签名配置继续不出现在面板中。

## 动态更新与空状态

执行中心既有 1.5 秒轮询继续使用。每次刷新后重新拉取当前选中任务的详情，并在状态变化时更新结论、进度和时间线。任务完成后停止轮询，结论和报告入口保持可见。

没有选择任务时显示引导空状态；任务不存在或已被清理时清空选中状态并回退到列表第一项。

## 验收标准

1. queued/running、passed、failed、需关注四种结论均有可区分的视觉状态和正确文案。
2. 批量任务可显示关联运行的步骤进度、当前步骤及首个失败信息；单条任务显示自身步骤。
3. 通过但存在重试的任务显示“需关注”；无重试通过显示“通过”。
4. API 与 Web 证据摘要不泄露敏感字段，报告入口可用。
5. 执行中心列表、质量报告、资产发起执行和现有全量测试不回归。
