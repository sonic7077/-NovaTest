# 一日女友接口自动化设计

**日期：** 2026-08-13
**项目：** 一日女友
**范围：** 将《一日女友-API接口文档》中的普通 REST 接口接入先锋营自动化测试平台，并生成不少于 100 条可执行接口用例。

## 目标与边界

项目测试环境为 `https://daygf.chenmoyuan.tech`。接口使用 JSON 请求与标准 JSON 响应，用户鉴权同时支持 `x-token: <JWT>` 和 `Authorization: Bearer <JWT>`。

平台新增“一日女友”项目和专用 REST 协议；项目运行配置保存测试基址、用户名和密码。账号密码只保存在 SQLite 运行配置，绝不写入种子文件、源码、测试报告、数据包说明或 Git。报告对 `password`、`token`、`authorization`、`refresh_token` 等字段一律显示为 `********`。

本期不包含删除、改密、上传真实文件、发布内容、提交入驻/签约、下架、收藏、评论、点赞等会持续改变测试账号状态的正向执行。它们只在不产生业务数据的未认证、错误参数或权限反例中覆盖。`DELETE` 路径全部不生成执行用例。

## 协议与执行模型

新增 `daygf` API runner，职责是调用文档定义的 `/api/*` REST 接口：

1. 对 `auth: session` 的第一个步骤调用 `POST /api/login`，请求体由 SQLite 运行配置提供。
2. 从成功响应提取 `token` 和 `refresh_token`，保存到当前批量任务的 `daygf` session。
3. 同一批次内所有一日女友用例复用同一个登录 session；不会为每条用例重复登录。认证请求失败后本批后续用例保留明确失败原因，不会使用旧 Token。
4. 用户接口同时带入 `x-token` 与 Bearer Token。无认证反例明确设置 `auth: none`，不会触发登录。
5. 统一支持 `GET`、`POST`、`PUT`、`DELETE` 的 URL 参数、JSON body、预期 HTTP 状态码、JSONPath 存在/等值断言及变量提取。
6. 每个步骤报告保存脱敏后的请求摘要、HTTP 状态、耗时、响应摘要及断言结论；失败同样保存请求与响应证据。

协议配置在现有 SQLite runtime config 中增加 `daygf` 对象：`baseUrl`、`username`、`password`。配置缺失时，runner 只报告“项目运行配置未完成”，不尝试网络请求。

## 用例资产

用例采用现有 `test_cases` / `test_steps` 表及 API 资产页，不新增表。每条用例归属于“一日女友”项目，`target: api`，`request.protocol: daygf`。服务启动时以稳定 ID 幂等写入；用户在页面修改的同 ID 用例由种子更新，新增的用户用例不受影响。

### 高风险接口处理

以下接口不加入可执行正向集：

- 权益或资金变更：`POST /api/unlock`、`POST /api/shop/vip/orders`、`POST /api/shop/coin/orders`、`POST /api/shop/order`、`POST /api/shop/pay/callback/:channel`。
- 持久化写入：注册、资料修改/改密、浏览历史、收藏、评论、互动、发布、女友提交/分享、入驻/签约申请、上传、下架与删除。

商城保留配置、订单列表、流水和订单状态只读查询。资金接口只允许无 Token、非法参数和不存在订单等安全反例；不发起创建订单、支付回调或解锁请求。未来如提供专用沙箱、可回滚测试商品与书面授权，可新增独立高风险用例集，并保持默认禁用且要求 `allowMutations: true`。

## 批量、报告与失败处理

- 一日女友 API 用例只能和同项目、同 target、同 protocol 用例组成一个批次，沿用现有批量校验。
- 批次创建一个共享 `daygf` session，正常 Token 在全部用例中复用。刷新 Token 用例使用独立会话，避免令主批次 session 失效。
- 运行报告按用例显示请求路径、方法、状态码、耗时、断言、脱敏请求/响应；汇总显示通过、失败、跳过和每模块统计。
- 网络错误、非 JSON 响应、认证失败、状态码不符和 JSON 断言失败均记录为可定位错误。列表为空而后续必须提取 ID 时使用 `PRECONDITION_UNAVAILABLE`，标记跳过。

## 验证

实现阶段将先补充协议验证、会话复用、脱敏、无认证、变量提取、资金阻断及 110 条种子矩阵测试；再跑全量测试。随后启动本地服务，确认项目和用例已入 SQLite，并以不产生业务变更的只读冒烟集执行一次，检查批次报告中无密码或 JWT 明文。

## 非目标与风险

- 不执行任何真实支付、充值、扣费、解锁或支付回调。
- 不依赖管理员账号，文档中的后台摘要仅覆盖公开的前台站点接口；后台接口需要单独的授权与范围确认。
- 线上测试环境的数据量、内容 ID 和订单号不稳定；用例仅对文档承诺的结构和状态做断言，动态数据必须通过前置查询提取。
- 批量任务登录共享减少压力，但账号被并发使用或 Token 被服务端提前失效时会导致整批认证失败，报告应明确显示认证错误并可单独重试。
