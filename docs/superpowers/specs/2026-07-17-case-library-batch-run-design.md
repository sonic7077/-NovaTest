# 测试用例库与串行批量执行设计

## 目标

在现有 Web UI 自动化平台中提供可持久化的测试用例库，以及可选择多个用例并按顺序执行的批次任务。

## 范围

本阶段只编排 Web UI 用例，不改变 Midscene、Playwright 或模型配置方式。模型未配置时，批次中的每个用例仍创建独立运行记录，并以明确的配置错误结束；后续用例继续执行。配置完成后，相同批次流程无需修改即可进行真实浏览器执行。

## 设计选项

1. 串行批次，推荐：一次只运行一个用例，降低浏览器和模型资源竞争，并让顺序、日志与失败定位可预测。
2. 全并行批次：吞吐量较高，但浏览器实例、模型限流和截图写入会互相竞争，不适合作为第一个本地 MVP。
3. 外部队列：适合多机/CI 调度，但需要 Redis 或消息队列，超出当前本地平台范围。

## 数据模型

```ts
interface Batch {
  id: string;
  name: string;
  caseIds: string[];
  status: 'queued' | 'running' | 'passed' | 'failed';
  runIds: string[];
  startedAt: string | null;
  finishedAt: string | null;
}
```

批次和用例都保存在现有 `data/store.json`。每一个 `caseId` 均通过既有 `RunService` 创建独立运行记录。批次状态为 `passed` 当且仅当所有运行记录通过；只要存在失败，最终状态为 `failed`，但调度器仍继续执行剩余用例。

## 后端接口

- `GET /api/cases`：列出用例库。
- `POST /api/batches`：接收名称和 `caseIds`，创建并串行执行批次。
- `GET /api/batches`：列出批次历史。
- `GET /api/batches/:id`：读取批次详情以及关联运行记录。

请求中有不存在的用例 ID、重复 ID 或空选择时返回 HTTP 400，不创建批次。

## 前端

用例库列表增加复选框、选择计数和“批量执行”命令。创建批次后，在批次历史区域展示总体状态、通过数、失败数、开始时间及每个用例的报告入口。批次未完成前运行按钮不可重复提交。

## 验收

1. 创建的用例在重启后仍显示于用例库。
2. 可选择两个或更多用例创建批次。
3. 执行器以选择顺序串行调用，某一用例失败后后续用例仍会执行。
4. 批次和单用例运行记录可在重启后读取。
5. 未配置模型时，批次结果明确显示配置失败，而不是显示为通过。
