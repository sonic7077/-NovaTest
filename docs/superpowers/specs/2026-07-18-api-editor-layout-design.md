# API 编辑器布局修复设计

## 目标

修复接口测试用例编辑器在桌面视口中将表单挤压为窄列的问题，并让顶部面包屑准确反映当前编辑的用例类型。

## 根因

接口步骤节点仅包含步骤序号和内容两个网格子项，却继承了 Web UI 步骤的四列 `.step` 网格。内容因此被分配到第二个 28px 的列中。编辑页面包屑也未读取当前 `target`，而是固定显示 Web UI 文案。

## 设计

- 保持通用 `.step` 的 Web UI 四列布局不变。
- 为 `.api-request` 覆盖为 `28px minmax(0, 1fr)` 的两列布局。
- 为 API 内容容器和字段增加最小宽度约束，确保长 URL、JSON 和表单元素可以在剩余列内收缩、换行或滚动，不产生布局挤压。
- 在路由渲染阶段根据编辑器 `target` 输出“接口用例编排”或“Web UI 用例编排”。编辑 API 用例时，异步加载的数据抵达后由既有 `applyCase()` 同步一次面包屑。

## 验收标准

- API 步骤中的标签和控件在桌面编辑器内以正常横向宽度展示。
- Web UI 步骤保持现有四列布局。
- 新建 API 用例及编辑既有 API 用例均显示“接口用例编排”。
- 新建和编辑 Web UI 用例仍显示“Web UI 用例编排”。
- 静态回归测试覆盖 API 布局覆盖规则和面包屑的类型分支。
