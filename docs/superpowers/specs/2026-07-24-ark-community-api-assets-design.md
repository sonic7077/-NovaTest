# 方舟社区发帖查询接口资产设计

## 目标

根据社区接口说明与现有 Python 测试脚本，补足“方舟社区发帖”项目中尚未独立管理的只读接口测试场景。现有配置、帖子列表、评论列表和用户资料修改记录查询资产继续保留，不创建重复资产。

## 范围

新增四条 API 用例，均归属名称为“方舟社区发帖”的项目，目标类型为 API，使用 `POST` 请求，安全级别为 `readonly`：

| 用例名称 | Action | 覆盖范围 | 预期业务状态 |
| --- | --- | --- | --- |
| 帖子状态筛选查询 | `list_post` | `status=10/0/1/2/3`、分页及列表响应结构 | `1` |
| 评论状态筛选查询 | `list_post_comments` | `status=0/1/2`、分页及列表响应结构 | `1` |
| 用户资料审核状态筛选查询 | `list_member_update_log` | `status=10/0/1/2`、分页及列表响应结构 | `1` |
| 无效登录态拦截 | `list_post` | 隔离的非法令牌调用 | `0` |

每一种状态筛选作为同一用例内的独立步骤，便于报告精确定位。无效登录态用例不使用或覆盖批任务的共享会话。

## 落库与执行

- 通过项目名称查找“方舟社区发帖”，不得硬编码项目 ID。
- 用例按稳定名称幂等创建或更新；重复执行初始化不会生成重复资产。
- 正常业务步骤不保存登录接口步骤。执行器在批任务内按需登录一次，并只在内存中复用令牌。
- API 资产与运行记录中不得保存账号、密码、Google 验证码、令牌、AES 密钥、IV、签名、密文或原始加密表单。

## 报告与失败证据

- 报告展示脱敏后的请求概要、HTTP 状态、业务状态、耗时、断言结果和已解析的响应内容。
- 失败步骤同样保留安全的请求和响应摘要，便于定位错误；敏感字段使用掩码。
- 若运行环境缺少 CMS 配置，仅报告缺失环境变量名称，不读取或输出其值。

## 验收标准

1. “方舟社区发帖”项目中可见四条新增用例，且重复初始化不产生同名重复项。
2. 现有四条基础查询资产仍可用，不被删除或改写为风险操作。
3. 在运行环境配置完整时，新增的三个查询用例和一个权限拦截用例均可执行并生成报告。
4. 批量执行正常查询用例时仅发起一次登录，响应报告不暴露敏感信息。
5. 不实现或执行发布、审核、回复、删除等会修改远程数据的接口用例。
