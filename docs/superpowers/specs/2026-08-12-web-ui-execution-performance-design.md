# Web UI 自动化执行性能优化设计

**日期：** 2026-08-12  
**范围：** 无极灯塔 Web UI 自动化执行时长优化

## 背景与证据

本地平台 `http://127.0.0.1:4173` 已执行只读用例“无极灯塔 - 任务清单只读识别”。该用例仅包含一个读取任务列表的步骤，首次尝试即通过、无视觉基线比较、无重试，但总耗时为 248.5 秒。

当前步骤类型为 `action`，Web Runner 因此调用 Midscene `aiAct`，使“查看并确认”类纯验证任务进入可多轮的页面操作规划。当前 `replanningCycleLimit` 默认值为 40。运行时登录和截图仍需保留，但不是该基线中确认的主要耗时来源。

## 目标

- 将纯验证类 Web UI 步骤从行动规划路径切换到断言路径。
- 将实际行动步骤的 Midscene 规划轮次限制由默认 40 调整为 8。
- 保留 Lighthouse 登录、单步失败后一次重试、成功/失败截图和报告证据。
- 以当前只读用例为回归基线，验证优化后仍可通过，并记录实际时长；不将特定秒数作为硬编码通过条件。

## 设计

### 用例语义

- “无极灯塔 - 任务清单只读识别”的唯一步骤改为 `assert`：确认“我负责的”列表已加载并可见任务内容，不创建、编辑、删除或变更状态。
- “无极灯塔 - 任务清单识别与新建任务”保持混合语义：打开/读取与最终结果验证使用 `assert`；点击新建、选择清单、输入标题、创建任务使用 `action`。
- 不根据自然语言关键词在执行期猜测步骤类型。用例保存的 `kind` 是唯一执行依据，避免误把业务操作降级为断言。

### Midscene 规划限制

- 在 `createMidsceneAgentFactory` 中继续通过环境变量 `MIDSCENE_REPLANNING_CYCLE_LIMIT` 支持显式覆盖。
- 未配置、无效或超出边界时，默认上限从 40 改为 8；允许值范围仍为 1 至 80。
- 该设置仅作用于 `aiAct` 的规划轮次。`aiAssert` 直接执行视觉/DOM 断言，不进入行动规划流程。

### 可靠性与报告

- `RunService` 维持每步最多两次尝试；首轮失败仍保存失败截图并记录“retrying once”。
- `WebRunner` 继续在每次成功操作或断言后保存截图；失败时同样保存证据。
- 不改变 Lighthouse 账号密码登录、二次验证码、公司选择或项目级共享登录行为。

## 验证策略

1. 为默认规划上限 8 与显式覆盖行为增加单元测试。
2. 为只读灯塔步骤保存为 `assert` 增加种子/升级测试。
3. 运行 Web Runner、Lighthouse 登录、生产 Runner 和全量测试。
4. 重启固定端口 4173，执行只读用例，检查结果、截图、报告与实际耗时。
5. 不自动运行会创建任务的完整用例；它会产生真实业务数据，应在单独授权后执行。

## 非目标

- 不删除截图、不取消重试、不修改模型供应商或模型密钥。
- 不改变 API 测试执行策略。
- 不新增并发 Web UI 执行，因为同一外部站点的登录和写操作会降低可重复性。
