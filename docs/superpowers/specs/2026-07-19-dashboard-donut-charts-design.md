# 工作台动态饼图设计

**日期：** 2026-07-19  
**状态：** 已确认，等待规格审阅

## 目标

将工作台现有的两块文本统计面板升级为基于真实完成运行数据的动态可视化，并保持页面只展示质量概览，不引入执行过程、日志或模拟数据。

已确认采用方案 B：左侧保留每日执行趋势，并在其中汇总总体通过率；右侧以饼图展示 Web UI 与接口测试的运行占比。

## 范围

本次仅修改 `#/dashboard` 的下列两个区域：

1. `执行趋势`。
2. `执行类型`。

不改变工作台顶部指标、最近失败、最近报告、执行中心、质量报告、测试资产、模型配置、服务端数据模型或 `/api/dashboard` 接口契约。

## 数据与渲染

工作台继续在加载页面和切换“今日 / 最近 7 天 / 最近 30 天”时请求：

`GET /api/dashboard?range=today|7d|30d`

所有图表只消费该响应的终态运行聚合数据：

- `completedRuns`、`passRate`、`failedRuns`：总体质量圆环和摘要。
- `daily[]`：按日期的通过与失败运行趋势。
- `targets[]`：Web UI 与接口测试的完成运行数和通过运行数。

前端不再把这些数据拼接成多行文本。改为两个独立、可测试的渲染函数，均采用原生 SVG 圆环绘制，不引入外部图表依赖。

## 图表布局

### 执行趋势

左侧面板由两部分组成：

- 左侧动态圆环以绿色和红色分别表示通过与失败。圆心显示总体通过率；圆环旁显示通过、失败和完成运行数。
- 右侧以日期顺序展示每日柱状趋势。每根柱按通过/失败分段，柱高按该日完成运行总数相对当前所选范围的最大日运行数归一化。日期标签由服务端返回的 `daily[].date` 生成。

新数据到达后，圆环的 SVG `stroke-dasharray` 与趋势柱的高度以 CSS transition 平滑更新。动画只表达真实数据的刷新，不使用计时器生成伪造执行进度。

### 执行类型

右侧面板用动态圆环按完成运行数展示类型占比：

- 蓝色表示 Web UI。
- 橙色表示接口测试。
- 圆心显示所有类型的完成运行总数。
- 图例显示各类型名称、完成运行数和各自通过率；通过率按 `passedRuns / completedRuns` 计算。

未知 `target` 不纳入饼图，防止历史迁移中缺失类型的数据被错误归类。已知类型均不存在时显示空状态。

## 空状态与容错

- 当 `completedRuns` 为 `0` 或对应聚合数组为空时，相关面板显示“所选时间范围内暂无已完成执行记录”。
- 缺失、非数值或负数统计值在渲染前归零，避免 SVG 路径、百分比或柱高产生 `NaN`。
- 类型完成数为 `0` 时通过率显示 `--`，避免除零。
- 保留现有请求失败提示，由 `loadDashboard()` 的调用方显示错误 toast；加载失败不以旧图表数据伪装为新统计。

## 可访问性与响应式

- 每张 SVG 具有可读的 `role="img"` 和描述总体数值的 `aria-label`；图例同时提供文本数值，颜色不是唯一的信息来源。
- 桌面端趋势圆环和每日趋势并排，类型圆环和图例并排。
- 窄屏下，面板内部切为单列，趋势柱仍保持可读宽度并允许区域内横向滚动；文本、图例和指标不得溢出。

## 验收标准

1. 工作台两个面板均不再输出原始的多行文本统计。
2. “执行趋势”同时包含通过率圆环和基于 `daily[]` 的每日通过/失败趋势。
3. “执行类型”按 `targets[]` 正确展示 Web UI 与接口测试的真实完成运行占比及各自通过率。
4. 切换时间范围后，顶部指标和两张图表均以相同接口响应刷新。
5. 无数据、仅单一类型和仅失败运行均能正常展示，且不出现 `NaN`、除零或模拟数据。
6. 现有页面结构检查与完整自动化测试继续通过，并在桌面与窄屏浏览器中验证布局。
