# BY 全接口反例矩阵设计

## 背景

BY 项目现有资产只覆盖 Web/H5 公共接口，约 29 条用例。`web-h5-api-reference.md` 和 `admin-api-reference.md` 还定义了管理后台的认证、会员、文章、举报、站点配置、RBAC、采集审核、Telegram 用户和订单接口。目标是在同一个 BY 项目中将已知接口转化为不少于 200 条可追溯的正例、反例和边界用例。

## 目标

- 在 BY 项目中保有不少于 220 条唯一、稳定标识的接口测试用例。
- 支持公共 `/c-api/v1` 与后台 `/admin-api/v1` 两套协议、鉴权和响应契约。
- 对每条接口覆盖正常请求、缺失必填、错误类型、边界、非法枚举、分页、编码字符和安全输入场景。
- 后台登录只在一次批量任务内执行一次，并复用短期 JWT；JWT、TOTP、密码、联系方式和第三方密钥均不进入用例、报告或 Git。
- 所有有副作用的接口均可被平台编排，但默认不执行；仅在执行时显式授予变更权限后才会调用。

## 非目标

- 不模拟支付成功回调、Telegram 登录验证码、外部 Telegram 同步或频道发送。
- 不默认执行删除、批量删除、密码重置、2FA 重置、账号创建、角色或菜单修改、发布推送、会员状态修改、举报处理、VIP/封禁变更等高影响操作。
- 不使用真实攻击利用链、扫描器、并发轰炸或绕过鉴权；安全场景只验证服务端对受控输入的校验和错误响应。

## 架构

新增 `byAdmin` API 协议和 `ByAdminApiRunner`。公共 `by` 协议保持只允许 `/c-api/v1/*` 的同源路径；后台协议只允许 `/admin-api/v1/*` 的同源路径。二者均使用统一请求证据结构，记录 HTTP 状态、业务码、耗时、经脱敏的请求摘要和响应摘要。

后台执行器拥有批次内 API 会话：首次需要认证的步骤读取 SQLite 运行时配置中的 BY 后台测试账号并调用登录接口，按配置生成 TOTP，保存内存 JWT；后续步骤自动复用。遇到 401 时仅刷新或重新登录一次。认证配置缺失时，要求 JWT 的用例产生“前置认证配置缺失”跳过结论，而不是失败。

用例仍写入既有 `test_cases` 和 `test_steps` 表。请求 `protocol` 扩展为 `byAdmin`，结构化字段沿用 `action`、`method`、`payload`、`expectedStatus`、`expectedJson`、`extract` 和 `safety`。不新增业务数据表；运行时配置使用现有 SQLite 配置持久化机制。

## 执行分层

| 层级 | 含义 | 默认行为 |
| --- | --- | --- |
| P0/P1 只读 | 公共查询、后台已鉴权查询、鉴权拒绝与输入拒绝 | 默认执行 |
| P1/P2 受控变更反例 | 缺字段、非法状态、无效 ID、格式错误等应在持久化前失败的写请求 | 默认执行，必须以文档确认的错误码或状态为断言 |
| P2 受控变更正例 | 举报、编辑、发布、审核、配置、推送等可能创建或改变业务数据的请求 | 仅 `allowMutations` 显式授权时执行 |
| P3 高风险/外部 | 删除、支付回调、Telegram 连接/验证码/同步/推送、密码与 2FA 重置 | 存为跳过型资产，报告固定显示风险原因，不发起请求 |

`DELETE` 方法在协议校验层禁止执行。即使调用者传入 `allowMutations`，高风险层仍不会向外部接口发送请求。

## 用例矩阵

### 公共 Web/H5：至少 130 条

- 会员列表与详情：分页边界、组合筛选、区间反转、空值、无效路径标识、Unicode、URL 编码、长度边界、排序白名单回退、上架数据隔离、列表到详情链路。
- 图片：无效、空、超长和编码异常 Token 的拒绝；不保存图片二进制或 Token。
- 举报：必填字段、长度 64/512/128 边界、错误 `targetType`、不存在会员、空白字符、UTF-8 多字节、保守的 SQL/XSS 特征文本拒绝，以及显式授权下的成功链路。
- 文章、公告：分页、分类、关键词、详情 ID、未发布资源、排序和内容字段契约。
- 公共配置：客服、地区、友情链接、站点、落地页、回家路的响应信封、启用项过滤和必要字段契约。

### 管理后台：至少 100 条

- 认证：登录成功、缺用户名/密码、错误凭据、错误/过期 TOTP、刷新、未认证、错误 Bearer 格式、当前账号与路由权限。
- 会员管理和推送：查询参数、非法 ID、创建/编辑/状态/联系方式状态/批量状态的前置校验，以及只读循环统计和批次查询。
- 内容和举报：文章/公告和举报列表，创建、编辑、状态、批量操作、处理举报的缺字段、长度、状态枚举和不存在资源反例。
- 文件和敏感联系方式：无授权、非法资源、一次性授权链路中的失效 Token 和不匹配资源；不读取或落盘任何明文联系方式。
- 站点配置、看板、日志：查询字段契约，完整对象更新的缺失字段反例。
- 账号、用户、角色、菜单：未授权与权限不足、分页、非法 ID、重复/错误字段、菜单 ID 结构校验。实际创建、删除、密码/2FA 重置均为高风险跳过型资产。
- Telegram 与采集审核：全部状态查询、无效查询参数和缺失字段反例；审核通过、推送、连接、验证码、同步、封禁、VIP、支付回调等记为高风险跳过型资产。

每条用例名称体现优先级、正反例、模块和场景，ID 使用 `by-public-*` 或 `by-admin-*` 前缀。种子生成必须在重复启动时按 ID 覆盖更新，不能累积重复记录。

## 测试数据与安全输入

反例数据由可复现的静态集合产生：空值、空白、布尔/数组/对象类型错配、零与负数、最大安全整数、极小或极大分页、64/65 与 512/513 等文档边界、中文、英文、emoji、组合 Unicode、替换字符、URL 编码字符和有限长度的 SQL/XSS 特征文本。特征文本不得包含可执行脚本、数据导出、认证绕过、命令执行或高频探测内容。

写操作的“成功”用例只使用运行时先查询并提取的测试数据。执行器对步骤证据中的 `password`、`token`、`authorization`、`secret`、`contact`、`hash`、`apiId`、`qrCodeData`、`setupToken` 和任意配置密钥脱敏；URL 中同类参数也脱敏。

## 失败与报告

- HTTP 状态、业务码、JSON 字段断言任一不符时，报告保留脱敏后的请求与响应，结论为失败。
- 缺失测试账号、TOTP 配置或可供提取的前置数据时，使用明确的跳过结论，区分环境问题和接口缺陷。
- 对默认禁用的高风险资产，报告显示“未执行：高风险操作需要独立授权”，不显示为通过。
- 批量报告按用例汇总通过、跳过和失败，并保留每个后台请求的认证是否复用、重试次数和耗时。

## 验证

- 先增加失败的领域校验、执行器、会话复用和种子计数测试，再实现最小代码使其通过。
- 验证同一批 BY 后台任务仅登录一次，401 时最多恢复一次，且敏感字段从报告中移除。
- 验证种子总量不少于 220、ID 唯一、项目归属正确、受控和高风险分层正确。
- 在不提供后台凭据的情况下执行公共 P0/P1 用例与后台无认证反例；有凭据时再执行后台只读和受控反例。受控变更正例与高风险资产不作为默认全量运行的一部分。
- 完整运行现有自动化测试套件，并只在全部通过后更新 SQLite 数据包。

## 假设与待配置项

- BY 后台测试环境为 `https://by.chenmoyuan.tech`，路径前缀为 `/admin-api/v1`。
- 后台测试管理员、密码和 TOTP 秘钥由部署侧写入 SQLite 运行时配置；本次不假设、猜测或内置凭据。
- 文档未定义的写接口精确成功响应不作为成功正例断言；仅生成输入拒绝、鉴权和风险隔离用例，直到提供测试数据契约。
