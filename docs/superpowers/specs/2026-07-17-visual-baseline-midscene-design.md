# Midscene 视觉基线用例设计

## 目标

让 Web UI 功能用例在自然语言步骤之外保存步骤级参考截图，并由 Midscene 结合步骤描述、参考截图和当前页面截图判断流程状态，从而降低动态页面下纯文本断言的不稳定性。

## 范围

- 每个 Web UI 步骤可绑定零到多张视觉基线。
- 支持本地上传图片和从一次已完成运行的截图提升为基线。
- 视觉判断采用 Midscene 语义比较，不做全图像素级失败判定。
- 视觉判断结果、理由、基线和当前证据全部写入运行报告。
- 不增加区域编辑器、像素阈值、对象存储、图像版本分支或 API 用例基线。

## 用例模型

步骤新增 `visualChecks` 数组：

```js
{
  id: 'visual-uuid',
  assetPath: 'case-id/visual-uuid.png',
  source: 'upload' | 'run',
  description: '订单确认页需展示商品名称、金额和提交按钮'
}
```

图片资产保存在 `data/case-assets/<caseId>/`，路径为相对路径。步骤保存时验证 `description` 非空、路径属于当前用例目录且文件已登记。无 `visualChecks` 的旧步骤保持原有 Midscene 行为。

## 编辑流程

每张步骤卡片增加“视觉基线”区：上传按钮、已绑定缩略图、说明输入、删除图标和“从运行截图设为基线”入口。

上传通过 `multipart/form-data` 写入临时资产，返回资产 ID 和预览 URL；保存用例时将选择的资产绑定到步骤。运行报告中的截图可通过“设为基线”调用提升接口，复制到用例资产目录并要求填写或确认视觉说明。

## 执行流程

1. WebRunner 完成既有 `aiAct`、`aiAssert` 或 `aiQuery`，并保存当前步骤截图。
2. 若步骤含视觉基线，Runner 为每个基线调用 Midscene 视觉判断，提示词固定说明：以步骤 `instruction` 和 `description` 为验收条件，判断当前页面是否满足参考状态，忽略时间、随机标识、广告和非关键动态文案。
3. 任一基线判断失败或模型无法得出可靠结论时，抛出带视觉理由的步骤错误；既有重试机制会重新执行并保存新证据。
4. 成功时，Runner 返回 `visualChecks` 运行结果；失败时通过错误对象返回已完成的比较结果。

## 接口

| 方法 | 路径 | 行为 |
|---|---|---|
| `POST` | `/api/cases/:caseId/assets` | 上传 PNG/JPEG/WebP，返回临时视觉资产 |
| `GET` | `/api/cases/:caseId/assets/:fileName` | 返回已绑定或临时资产图片 |
| `POST` | `/api/cases/:caseId/visual-baselines` | 从指定运行截图复制为该用例视觉资产 |
| `DELETE` | `/api/cases/:caseId/assets/:assetId` | 删除未被步骤引用的临时资产；已引用资产在保存时由服务端清理 |

所有图片读取均以数据库引用和 case ID 为白名单，不暴露资产目录。上传限制 PNG/JPEG/WebP，单文件最大 5MB。

## 报告

每个步骤报告增加视觉判断区：基线缩略图、当前截图、模型结果（通过/失败/不确定）和判断理由。报告读取运行快照，不依赖仍存在的测试用例；删除用例后历史报告仍完整可读。

## 错误处理

- 没有配置 Midscene 模型时，含视觉基线的用例不可执行，返回明确配置错误。
- 上传类型、大小、路径、运行归属或截图白名单校验失败时返回 `400` 或 `404`。
- 基线图片读取失败或模型比较失败时保留当前截图和错误理由，并按既有一次重试处理。

## 测试验收

1. 用例创建、更新与 SQLite 重启后保留步骤视觉基线。
2. 上传拒绝不支持的文件类型、超限文件及跨用例资产引用。
3. 从本运行已登记截图提升基线成功；伪造运行或截图返回 `404`。
4. 有基线步骤会触发 Midscene 视觉判断，失败理由进入步骤运行记录和报告。
5. 无基线步骤保持现有执行路径。
6. 编辑页可以上传、预览、删除和保存视觉基线；报告展示基线、当前截图和模型理由。
