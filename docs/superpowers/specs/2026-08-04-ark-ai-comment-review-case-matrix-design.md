# 方舟 AI 评论审核正反例用例矩阵设计

## 目标

将“方舟AI评论审核”项目的接口用例扩展到固定 60 条，以可重复的正反例覆盖 AI 评论与 AI 评论审核接口的查询、筛选、参数校验和鉴权边界。

## 数量与分层

用例总数为 60 条，其中保留现有 4 条：

- `AI 评论概览查询`、`AI 评论审核列表查询`：只读正例。
- `AI 评论人工通过闭环`、`AI 评论人工驳回闭环`：已有受控写操作；只有 `allowMutations: true` 时执行，待审核数据不足时跳过。

新增 56 条只读用例：36 条正例和 20 条反例。每条用例使用固定 ID，可重复执行种子函数覆盖更新，不会创建重复资产。

## 正例矩阵

正例按接口与典型筛选维度拆分：

| 接口 | 覆盖内容 |
| --- | --- |
| `ai-comment/summary` | 默认日期、指定日期、项目 ID、日期与项目组合、空授权项目结果结构 |
| `ai-comment/configs` | 列表结构、默认配置字段、启用状态、数值范围字段、评论规则字段 |
| `ai-comment/records` | 默认查询、日期、项目、日期与项目组合、`limit` 的 1/20/50/200 边界 |
| `ai-comment-review/list` | 默认列表、各审核状态、AI/用户来源、内容模糊查询、评论 ID、文章 ID、日期范围、分页、`limit` 的 1/20/50/200 边界 |
| `ai-comment-review/stats` | 全局统计、项目统计、统计字段非负、数值类型 |

每条正例断言 HTTP 200 和接口文档中的稳定结构字段；不对测试服中易变的总数、评论文案或具体记录数量做硬编码断言。

## 反例矩阵

反例不产生业务副作用，使用以下模式：

- 未认证请求：对摘要、审核列表和统计接口使用 `auth: none`，预期 HTTP 401。
- 参数校验：审核列表的非法日期、非法页码、非法 `limit`、非法状态、非法来源；生成记录和概览的非法日期或无效项目 ID。
- 非法资源：不存在项目 ID 的查询与统计，接受接口文档定义的 403 或 404；用例为可配置期望状态集合，报告保存实际状态和响应摘要。
- 类型边界：字符串项目 ID、负数项目 ID、超大项目 ID、日期范围颠倒、超长关键词。

系统需扩展 `expectedStatus` 为单个数值或允许数值列表。列表场景只在实际状态属于允许集合时通过，避免测试服权限差异造成误报。

## 执行与安全

所有新增用例的 `safety` 均为 `readonly`，批量执行不需要写操作授权。无 Token 反例必须跳过会话登录，不能把认证 Token 写入用例变量、SQLite、报告或日志。新增用例与既有 Editorial 用例在同一批次内共享一次 JWT 登录。

`delete`、`trigger`、配置 PUT、开关 PUT、越权写操作以及额外的审批动作不纳入用例矩阵。

## 报告与维护

报告展示请求方法、Action、HTTP 状态、耗时和脱敏响应摘要。对于状态集合断言，报告应展示允许的状态集合和实际 HTTP 状态。种子模块使用数据驱动的案例定义，按端点与参数矩阵生成用例，避免复制 56 份相同结构的代码。

## 验证

单元测试验证：总数恰好为 60、所有新增用例为 Editorial 只读协议、无删除或触发 Action、反例的认证与预期状态结构正确、状态集合断言正确工作。集成验证：批量执行全部只读用例，记录通过、跳过和因测试服实际权限差异产生的结果；报告不得包含凭据、TOTP 或 JWT。
