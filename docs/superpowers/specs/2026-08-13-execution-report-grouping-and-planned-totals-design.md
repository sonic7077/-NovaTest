# 执行报告分组与固定总量设计

**日期：** 2026-08-13  
**范围：** 批次报告、执行中心详情、批次任务统计

## 目标

1. 批次报告将用例按最终状态归类，失败、跳过、通过分别集中展示。
2. 执行详情在顶部结论区域提供测试报告入口，任务结束后可直接打开。
3. 批次创建时固定计划用例数与计划步骤数；执行期间仅完成数量递增，总数不随 run 创建而变化。

## 数据模型

`test_batches` 新增两个非空整数字段：

- `planned_case_count`：创建批次时所选用例数。
- `planned_step_count`：创建批次时对所选用例 `steps.length` 的求和。

`ExecutionService.queueBatch` 与同步 `BatchService.start` 都在创建 batch 时写入这两个值。内存存储使用相同字段。现有历史批次因没有字段或字段为零时，执行列表回退到已有 `caseIds.length` 与已生成 `run_steps` 计数，避免历史任务无法展示。

执行中心列表和详情优先使用计划总量：

- 完成用例：终态 run 数 / `planned_case_count`。
- 完成步骤：终态 step 数 / `planned_step_count`。
- 进度百分比：完成步骤除以计划步骤；计划步骤为零时显示 0%。

## 报告呈现

批次报告顶部仍显示可跳转的通过、跳过、失败汇总标签。正文按以下固定顺序输出三个区块：

1. 失败用例
2. 跳过用例
3. 通过用例

每个区块只在存在对应状态用例时显示，区块内保持 `batch.runIds` 的原执行顺序。区块标题提供状态与数量，并作为汇总标签的跳转目标。单条用例报告不改变。

## 执行详情

`renderExecutionDetail` 先构建顶部结论区。若任务已处于 `passed`、`failed` 或 `skipped`，则将“查看测试报告”按钮放入该区域右侧，与目标类型标签并列；执行中与排队中不显示该按钮。底部重复入口删除。

## 验证

- 存储迁移与内存存储测试：新批次会持久化计划总量，历史批次仍可读取。
- 执行服务测试：队列创建后，不生成 run 也有稳定的总用例/步骤数。
- 报告测试：三种状态的 runs 按失败、跳过、通过分段，汇总标签能跳到对应分组。
- UI 测试：完成任务的报告按钮在结论区，运行中不出现；详情统计使用固定总数。
- 全量 `npm test` 与本地批次执行，观察执行中的总量不变化。

## 非目标

- 不修改单条运行报告结构。
- 不改变批次串行执行、重试、步骤状态或报告导出格式。
- 不修改现有测试资产、模型配置、Web UI 自动化执行器或外部接口。
