# CMS Config 用例与解密报告设计

## 目标

在“方舟社区发帖”项目中创建一条可执行的 CMS `config` 只读接口用例，使用现有 AES-CBC 加密协议和懒登录会话复用能力执行，并在测试报告中展示完整、已脱敏的解密后业务响应。

## 用例模型

- 用例归属现有“方舟社区发帖”项目，类型为 API。
- 用例只包含一个 `config` 请求步骤：`POST`、空业务 payload、预期业务状态为 `1`，安全级别为 `readonly`。
- 用例不显式包含 `loginByPassword` 步骤。`CmsApiRunner` 在首次业务请求前读取运行环境配置、执行一次加密登录，并只在内存会话中复用 token。
- CMS 基础地址与加密、认证配置只能从运行环境变量读取；不得写入用例、测试数据、报告、日志或提交。

## 执行与证据

1. 执行器把公共客户端字段、内存 token 与业务 payload 组合为 JSON。
2. 请求使用 AES-128-CBC 加密为 `data`，生成 `timestamp` 和签名，以表单方式调用 `/api/remote/config`。
3. 执行器校验 HTTP 状态和 CMS 业务状态，解密响应体后运行 JSON 断言。
4. 运行步骤仅持久化请求摘要、HTTP 状态、业务状态、耗时以及解密后的业务响应摘要。

## 报告展示与脱敏

- API 步骤证据保留“请求摘要”。
- 原“响应摘要”更名为“解密后响应”，以折叠的格式化 JSON 展示。
- 敏感字段值以 `*` 替换，字段名保留以便排查结构。至少覆盖密码、token、密钥、加密 `data` 和 `sign`，并继承现有深层脱敏逻辑。
- 认证请求的响应始终显示为掩码，不展示任何登录返回内容。

## 失败处理

- 缺少 CMS 运行环境变量时，仅报告缺失变量名，并停止真实请求。
- 登录、解密、业务状态或 JSON 断言失败时，记录已脱敏的错误与请求证据，报告显示失败步骤。
- `config` 是只读接口；本次不允许任何写操作。

## 验收标准

- 方舟社区发帖项目可在资产列表中看到 `config` 接口用例。
- 单次执行仅发起一次登录和一次 `config` 业务请求。
- 报告可访问，显示“解密后响应”与格式化业务 JSON。
- 报告、数据库和证据中不出现明文 token、密码、密钥、`data` 或 `sign`；其值使用 `*` 掩码。
