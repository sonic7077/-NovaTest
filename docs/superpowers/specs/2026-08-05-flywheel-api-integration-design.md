# 飞轮引擎接口测试接入设计

## 目标

在平台中新增“飞轮引擎”项目，按飞轮对接文档保存、批量执行并报告 API 正反例。该接口使用 `X-Platform-Key` 鉴权和 `platform_id` 业务标识，与 CMS 加密接口和方舟 JWT 接口隔离。

## 范围与边界

覆盖健康检查、内容采集与状态回查、推荐流、搜索、内容详情、相关内容、行为反馈、词表查询与导入、用户建档，以及对应的鉴权、必填参数、分页、搜索边界和不存在资源反例。

`DELETE /api/v1/content/{content_id}` 与 `POST /api/v1/content/reconcile` 不创建用例：二者会删除或批量软删现有内容，无法用项目专属测试数据可靠隔离。其余写入接口按用户授权创建为可执行用例，不默认禁用。

## 运行配置

SQLite 的 `runtime_config` 新增可选 `flywheel` 分组：

- `baseUrl`：飞轮服务根地址。
- `platformKey`：请求头 `X-Platform-Key` 的唯一来源。
- `platformId`：所有项目专属测试数据的前缀和值来源。

运行配置状态接口只返回已配置状态和脱敏 Key。原始 Key 不得进入种子用例、前端状态、执行报告、SQLite 运行证据、日志、导出 HTML 或 Git 历史。环境变量仅用于首次初始化，服务后续从 SQLite 读取。

## 协议与执行器

新增 `flywheel` API protocol 及 `FlywheelApiRunner`：

1. 依据 `request.method` 构建 GET、POST、PUT 或 DELETE 请求；GET 参数来自结构化 payload，其他方法以 JSON body 发送。
2. 每次业务请求自动注入 `X-Platform-Key`、`Content-Type: application/json` 与稳定 `User-Agent`；测试定义不得保存明文 Key。
3. 对请求值执行变量插值，支持从采集响应提取 `job_id`、从状态回查提取 `content_id`，供后续详情、关联、反馈用例使用。
4. 根据 `expectedStatus`（单值或集合）与 JSON 路径断言判定步骤结果。即使 HTTP 状态属于预期反例，也保留已脱敏请求/响应证据。
5. `CompositeApiRunner` 根据 protocol 路由到飞轮执行器。飞轮会话只保存本批次产生的临时 ID，不保存 Key。

写入请求仍需沿用平台已有的 `allowMutations: true` 执行授权，以防批量执行入口在用户未明确允许时产生写入；资产本身保持启用，可单条和批量执行。

## 项目与用例集

启动种子以固定项目 ID 创建“飞轮引擎”，重复启动时仅补齐或更新同 ID 的用例，保留用户创建的资产。所有自建数据使用 `{{platformId}}-novatest-<run-id>` 前缀，避免碰撞。

| 类别 | 用例 | 预期 |
| --- | --- | --- |
| 可用性 | 健康检查、存活检查、指标端点 | 200，响应结构可读 |
| 读取正例 | 推荐流、搜索、词表查询 | 200，结果集合与字段结构正确 |
| 内容正例 | 采集、任务状态查询、详情、相关内容 | 采集返回 job；状态终态；有 content ID 时验证详情和关联 |
| 写入正例 | 用户建档、反馈上报、词表导入 | 文档约定的成功状态及响应字段 |
| 鉴权反例 | 业务请求省略 Key、使用错误 Key | 401 |
| 输入反例 | feed/search 缺 user_id；search 缺 q；非法或超界 size；空和超长 q | 422 或文档定义的校验错误 |
| 资源反例 | 不存在 content ID；非法 ingest job ID | 404 或 422 |

采集为异步流程：用例轮询状态到 `done`、`dup`、`blocked` 或 `failed`，终态、耗时和响应摘要均进入报告。只有 `done` 或 `dup` 且有 `content_id` 时，才执行详情、关联、反馈的后续断言；否则报告为明确的跳过或失败原因，而不是使用臆造 ID。

## 报告与错误处理

每个步骤保存方法、路径、参数或 body 摘要、状态码、耗时、断言结果、变量提取结果和响应摘要。敏感请求头及其衍生值统一替换为星号。网络错误、非 JSON 响应、超时、401/429、状态码不符和断言失败均保留可诊断的脱敏证据。

## 验证

单元测试覆盖配置校验与脱敏、协议路由、请求头、GET 参数编码、JSON body、状态码集合、变量传递、失败证据和写入授权。集成验证连接测试环境，先执行只读与反例矩阵，再以明确写入授权执行项目专属数据的采集、建档、反馈和词表导入；报告中检查 Key 从未出现。

## 非目标

本次不实现删除、批量对账清理、限流压测、生产数据回滚或前端新建表单的飞轮专属字段。现有 API 资产编辑器继续使用 protocol 与结构化请求字段，飞轮配置由 SQLite 运行配置管理。
