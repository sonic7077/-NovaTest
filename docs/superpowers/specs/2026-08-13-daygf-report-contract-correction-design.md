# 一日女友批次报告契约修正设计

**日期：** 2026-08-13  
**范围：** 一日女友 110 条接口用例及 `daygf` 执行器

## 结论

批次 `cf7c3462-bdc4-48a6-b9a3-8e782f7d1075` 的 48 条失败不应全部作为服务端缺陷。独立、无 Cookie、无 Token 的控制请求已确认 `/api/me`、`/api/profile/data`、`/api/coins`、`/api/content/mine` 与 `/api/shop/vip/orders` 均返回 `401`。批次失败的根因是共享 session 中的 Token 被 `auth: none` 负例复用。

## 变更

1. `auth: none` 必须完全匿名：不登录、不读取 session、不发送 `x-token` 或 `Authorization`。`auth: invalid` 仅发送固定错误 Token，亦不登录。
2. 保留所有鉴权负例。修正后它们应断言 `401`，用于发现真实鉴权回归。
3. 服务端以 HTTP `200` 与 `{ ok: false, msg }` 表示资源不存在的 4 条用例，改为断言 `expectedStatus: 200` 与 `$.ok === false`。不以消息文案作为稳定通过条件。原报告中其余未认证写请求是在 Token 泄漏后才进入参数校验；保持它们的 `401` 鉴权断言。订单状态接口在完全匿名请求下同样优先返回 `401`，因此保留鉴权断言。
4. 12 条分页、空查询及未知评论列表用例改为兼容性正例：断言 `200`、`$.ok === true` 与合法响应结构。零页码、超大页大小、空关键词、未知搜索类型均不再强制期望 4xx。
5. 执行器保留一次批量登录的 session 复用，仅改变匿名与错误 Token 两种请求的隔离方式。报告继续记录脱敏请求、状态、耗时与响应。

- 新增种子矩阵断言：指定业务拒绝和兼容性用例具有正确的状态码、JSON 断言与鉴权配置。
