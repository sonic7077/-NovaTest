# Web UI 步骤编排交互设计

## 目标

让 Web UI 用例作者能够明确区分页面操作与结果验证，在任何一个当前步骤内通过文件选择或系统粘贴快捷键添加图片，并能通过步骤菜单安全删除不需要的步骤。

## 范围

- 仅修改 Web UI 用例编辑器与 WebRunner 的提示词表达。
- 继续复用现有 `action` 与 `assert` 步骤类型、`visualChecks` 数据结构和图片上传接口。
- 接口用例编辑器不显示步骤图片、粘贴上传或 Web 步骤菜单。
- 不读取系统剪贴板权限；只处理浏览器已触发的粘贴事件中的图片数据。

## 步骤类型

新增 Web UI 步骤前展示两个明确选项：

| 类型 | 保存值 | 执行语义 | 图片语义 |
| --- | --- | --- | --- |
| 执行操作 | `action` | 根据描述继续操作页面 | 辅助模型定位、识别目标和理解页面上下文 |
| 验证结果 | `assert` | 校验此前步骤完成后的页面结果 | 作为期待状态和验收依据，与描述共同判断 |

已有 `action` 保持为“执行操作”，已有 `assert` 显示为“验证结果”；不自动改写已有用例。验证步骤没有图片时，仍以文字描述执行既有 `aiAssert`。有图片时，模型提示词明确该图片代表预期结果，忽略时间、随机编号和非关键动态内容。

## 图片输入

每张 Web UI 步骤卡保留上传按钮，并新增当前步骤范围内的 `paste` 监听。

1. 选择 PNG、JPEG 或 WebP 文件，或使用 `Ctrl/Command + V` 粘贴剪贴板图片，均调用相同的上传函数。
2. 粘贴事件仅在目标位于该步骤卡内、且剪贴板含受支持图片时被拦截；普通文字粘贴继续写入当前文本框。
3. 客户端和服务端均限制单图 5MB，上传期间锁定该步骤的图片输入，失败显示现有提示消息。
4. 上传成功后立即创建同样的图片预览与说明卡片，保存用例时通过既有 `visualChecks` 持久化。
5. 未保存的新用例仍提示先保存，不会创建无法归属的图片资产。

## 步骤菜单

每张 Web UI 步骤卡右上角的 `...` 打开该步骤范围内的菜单，提供“删除步骤”。删除后重新编号，不改变其他步骤的内容、图片或类型。若用例仅剩一个步骤，菜单动作不删除，并提示至少保留一个步骤，确保服务端的步骤必填约束始终可满足。点击卡片外部或再次点击菜单按钮会关闭菜单。

## 运行与报告

WebRunner 按 `step.kind` 构造图片上下文：

- `action` 的多模态提示说明图片为辅助识别资料，执行目标以步骤文字为准。
- `assert` 的多模态提示说明图片为预期结果资料，需验证当前页面与文字验收条件一致。

两类步骤均沿用当前的截图、逐图语义校验、失败理由和报告证据结构。图片不会使操作步骤变成验证步骤，也不会绕过现有的步骤失败与重试机制。

## 验收标准

1. 新增 Web UI 步骤可选择“执行操作”或“验证结果”，并保存为 `action` 或 `assert`。
2. 当前步骤能通过按钮或 `Ctrl/Command + V` 上传图片；文本粘贴保持正常。
3. `...` 菜单能删除任一非最后步骤，并即时更新编号。
4. 执行步骤和验证步骤在编辑器中有清晰标签，且图片用途不同。
5. 执行器测试验证两类步骤的多模态提示词，页面测试验证菜单、类型选择、粘贴监听与 API 隔离。
