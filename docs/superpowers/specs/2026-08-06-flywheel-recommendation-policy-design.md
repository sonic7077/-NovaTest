# 飞轮推荐策略分析用例设计

**日期：** 2026-08-06  
**项目：** 飞轮引擎  
**范围：** 基于 `taxonomy.json` 兴趣标签，对推荐接口前 20 条结果进行策略参数分析

## 目标

新增一条可重复执行的飞轮 API 用例：从附件标签词表中随机选择 1～3 个兴趣，创建隔离测试用户画像，调用推荐接口获取前 20 条内容，并依据当前参数配置输出可审计的推荐策略分析结果。

## 现状与约束

- 飞轮使用 `PUT /api/v1/users/{user_id}` 写入 `onboarding_tags`，不需要登录接口。
- 推荐接口为 `GET /api/v1/feed`，`size` 允许 1～50；本用例固定请求 20 条。
- 推荐条目的标签字段为 `tags: [{ tag, weight }]`，`reason` 仅在 feed 返回。
- 每次执行使用 `{{platformId}}-novatest-{{runId}}` 作为用户和会话标识，不触碰真实用户。
- 不调用删除、下架、对账或 taxonomy 导入接口。
- 随机选择必须由 `runId` 派生，重试时保持选择一致，并在报告中记录选择结果。

## 策略断言

对返回的 `items` 计算以下指标：

| 指标 | 配置依据 | 判定 |
| --- | --- | --- |
| 返回数量 | 请求 `size=20`、`POPULAR_LIMIT=20` | 1～20；少于 20 记录数据不足告警，接口为空则失败 |
| 前 2 条主兴趣保护 | `EXPLORE_HEAD_GUARD=2` | 前两条至少各命中一个所选兴趣 |
| 兴趣命中率 | `FEED_TAG_HIT_FLOOR=0.3` | 命中条数 / 返回条数不得低于 30% |
| 显式兴趣占比 | `FEED_INTEREST_CAP=0.8` | 命中条数 / 返回条数不得超过 80% |
| 内容去重 | `SEEN_TTL=7d`、会话抑制 | 本次 20 条 `content_id` 不重复 |
| 探索比例 | `FEED_EXPLORE_RATIO=0.15` | 仅当响应提供可识别探索标记时计算，否则标记为“接口未提供证据” |

兴趣命中采用标签名称精确交集；不使用模型或模糊语义推断。每条内容的命中标签、未命中标签和汇总比例写入该步骤的 API 分析证据。

## 执行流程

1. 从随代码发布的 taxonomy 资产读取标签名称，按 `runId` 稳定随机选择 1～3 个标签。
2. `PUT /api/v1/users/{userId}` 写入 `onboarding_tags`，断言 `$.ok=true`，提取选择变量。
3. `GET /api/v1/feed` 传入 `user_id`、`session_id`、`size=20`，断言 `$.items` 存在并执行策略分析。
4. 在报告中展示请求、响应、随机兴趣、逐条匹配明细、参数基线、告警和最终结论。

## 错误处理

- 标签资产为空、推荐响应不是数组、内容缺少 `content_id` 或标签结构非法：失败并保留 API 响应。
- 推荐少于 20 条：不把接口可用性误判为失败，但报告标记数据不足；若返回 0 条则失败。
- 任一硬性策略断言失败：该步骤失败，错误信息包含实际值和配置阈值。
- 重试复用同一 `runId` 和已选兴趣，不重新随机。

## 测试范围

- 单元测试：稳定随机选择、兴趣命中率/上限/前两条/去重计算、非法响应和边界值。
- 用例种子测试：中文名称、飞轮协议、PUT 建档与 size=20 feed 步骤、策略配置完整。
- 回归测试：现有飞轮 API runner、case 校验、全量测试。
- 测试环境实跑：使用真实飞轮测试服执行一次，报告不得包含平台密钥。

## 不在范围内

- 不修改飞轮服务端推荐算法或参数。
- 不将“reason”文本作为唯一正确性依据。
- 不自动导入附件 taxonomy 到线上词表；附件只作为测试兴趣数据源。
