# 测试报告 HTML 导出与结果锚点设计

## 目标

为单次执行报告和批量执行报告增加原始 HTML 下载入口，并让报告头部的通过、跳过、失败统计成为可点击标签，快速定位对应结果。

## 导出

- 报告页展示“导出 HTML 报告”按钮。
- 单次报告下载名为“用例名-测试报告.html”；批量报告下载名为“批量名称-测试报告.html”。文件名中的不安全字符替换为下划线。
- 下载接口复用现有 `renderReport` 和 `renderBatchReport` 的 HTML 输出，不另建 HTML 模板，也不改变在线查看格式。
- HTTP 响应使用 `Content-Disposition: attachment` 和 UTF-8 文件名，浏览器直接下载，不新开页面。
- 导出 HTML 保留内联样式、报告结构、截图链接、视觉校验及脱敏后的 API 证据；截图仍通过现有运行证据 URL 加载。

## 结果定位

- 报告头部把“通过”“跳过”“失败”呈现为可点击状态标签，包含对应数量。
- 批量报告中的标签分别指向第一个通过、跳过或失败的用例结果区段；每个区段拥有稳定的 DOM ID 和顶部滚动偏移。
- 单次报告的状态标签指向第一个拥有同一状态的步骤结果行。
- 某类状态数量为零时标签显示为禁用态，不提供无效锚点链接。
- 状态标签使用现有 `passed`、`skipped`、`failed` 色彩语义，键盘聚焦状态清晰可见。

## 服务端接口

- `GET /api/runs/:id/report`：保持在线预览行为。
- `GET /api/runs/:id/report/download`：下载单次 HTML 报告，缺失运行返回 404。
- `GET /api/batches/:id/report`：保持在线预览行为。
- `GET /api/batches/:id/report/download`：下载批量 HTML 报告，缺失批次返回 404。

## 验证

- 单元测试覆盖可安全下载的文件名、`Content-Disposition`、HTML 内容与在线报告一致。
- 报告渲染测试覆盖状态标签、有效锚点、零数量禁用标签和单次步骤定位。
- API 测试覆盖单次与批量下载成功以及不存在 ID 的 404。
- 完整测试套件通过，并用浏览器检查导出按钮和标签跳转。
