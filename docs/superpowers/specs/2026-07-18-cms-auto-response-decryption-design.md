# CMS 响应自动解密与报告展示设计

## 目标

兼容 CMS 同时存在“带 `crypt` 标识”和“仅在外层 `data` 提供 AES-CBC 密文”两种响应格式。平台在安全解密成功后，将完整业务 JSON 作为接口证据保存并在报告中展示。

## 响应解析边界

- `CmsApiRunner` 在校验 HTTP 与业务状态后，通过单一响应解析方法处理外层响应。
- 当外层 `crypt` 为真时，`data` 必须解密并解析为 JSON；解密或解析失败时步骤失败。
- 当 `crypt` 缺失或为假，且 `data` 是字符串时，执行一次兼容解密尝试：仅当 AES-CBC 解密并 JSON 解析都成功时，采用该对象作为业务响应。
- 兼容解密失败不影响未标记为加密的普通明文响应，仍将原 `data` 作为业务响应。
- 请求加密、`loginByPassword` 懒认证、内存会话复用、JSON 断言与变量提取的现有语义不变。

## 证据与脱敏

- API 步骤保存响应解析后的业务值，而不是外层 `data` 密文。
- 业务 JSON 的 `data` 字段可能是合法业务对象，必须递归保留，不能因字段名为 `data` 而整体掩码。
- 传输层 `data`、`sign` 和请求加密正文不进入运行证据。
- 业务对象中的 token、密码、密钥、IV、签名与同类敏感值统一替换为 `********`；认证响应继续整体掩码。
- 报告“解密后响应”展示格式化、已脱敏的业务 JSON。

## 失败处理

- 显式加密响应无法解密时，步骤失败并仅记录安全错误，不持久化密文。
- 无显式加密标识的响应解密失败时，回退到原始明文业务响应，不将探测失败视为测试失败。
- 自动解密不触发额外网络请求，也不改变只读与写操作安全策略。

## 验收标准

- `config` 可处理无 `crypt` 标识但 `data` 为 AES-CBC 密文的响应，并产出业务 JSON。
- 报告可展示嵌套业务 `data` 内容，而非密文字符串或全字段星号。
- 明文 CMS 响应仍可通过并保留原有断言语义。
- 报告、SQLite 运行证据和变量中不包含 token、密码、密钥、IV、签名或传输密文。
